「为了器官而器官」这个质疑我认，正面答一下这层抽象到底换来了什么——下面每个数都是我刚在本机跑出来的，可以自己复现。

**1. 工具 schema 不再全量塞进提示词**

按当轮命令的意图决定显影哪些能力。基准里 256 个能力定义、48 条代表性命令：冷启动平均只显影 36 个，**tool schema 这一块的 token 均值砍 84.71%**（中位 85.67%，最差一条 75.2%）。

```
git clone https://github.com/1420079678-ctrl/agent-body && cd agent-body
npm run bench:check     # 跟基线漂了就非零退出
```

真跑熟的机器没这么夸张——我这台 332 项里显影 128 项、省 58%，因为常用器官会保温。这个数 README 里也写着，没藏。被门控掉的能力没有消失，一次 `body_call` 就能取回。

**2. 卸掉一个插件，身体不该跟着塌**

六个内核（神经总线 / 心脏泵 / 主权层 / 反射引擎 / 解剖器 / 冲动传导）不依赖任何一个器官。实测把 dsh-office-docs 卸掉：craft 器官立刻判离线，**自动交给能力重叠最高的在线器官代偿**，核心完整性还是 6/6 全绿。压根没装的插件报「未安装」而不是「坏了」。

**3. 失败先归因，再决定要不要重试**

不是报错就重试。先做确定性归因（tool_missing / arg_error / permission / timeout / network / not_found / conflict / unknown），再按处方表处置：只读类自动执行，有副作用的留给我裁决，**arg_error 绝不自动重试**——参数错了重试只会把错误放大。

伤口要等**那个器官下次真的成功**才算闭合，不是自己宣布自己好了；超过 5 分钟没好就标 chronic 停止空转。我这台现在的账：伤口 200 / 未愈 0 / 已愈 197 / 愈合率 99%，自动止血 270 次。

另外同一个「工具 × 病因」失败累计 3 次，系统会**自己写出一条反射弧**，下次命中条件直接开火、零模型调用——目前自学 15 条，全在开火状态。
